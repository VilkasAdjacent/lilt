# Lilt: voice training

A personal voice-training app (in `app/`), plus the research and analysis behind it.

| Folder | What it holds | Published to Pages? |
|---|---|---|
| `app/` | The static web app, with no build step | Yes (`index.html`, `src/`, `vendor/` only) |
| `research/` | Targets, ranked changes, library comparison, sources, the 4-week prediction. **Gitignored**, local only | Never |
| `analysis/` | Python and Praat pipeline (`run.py`, `compare.py`, `targets.py`) | No |
| `bench/` | JS analysis-library benchmark against Praat | No |
| `recordings/` | Audio. **Gitignored** apart from `RECORDING_SCRIPT.md` | Never |

## Privacy

- **Audio and research stay out of git.** `research/` is gitignored because it contains personal measurements and intake context. All audio files and everything under `recordings/` are gitignored, and so are the measurements derived from them: `analysis/results/`, `analysis/cache/`, and the bench tracks. If you ever deliberately track audio (in a private repo only), `.gitattributes` sends it through Git LFS.
- **The app keeps audio on your device.** Recordings live in the browser's IndexedDB on the device and are never uploaded.
- **A public repo publishes the source as well as the site.** The Pages workflow publishes only the app, but on a public repo anyone can still browse the files.

## GitHub Pages setup (once)

1. Create an empty repo on GitHub (no README or licence). Then:
   ```sh
   git remote add origin git@github.com:<you>/<repo>.git
   git push -u origin main
   ```
2. On GitHub, go to **Settings → Pages → Build and deployment → Source** and choose **GitHub Actions**. Don't choose "Deploy from a branch", because that would publish the whole repo.
3. The `Deploy Lilt to GitHub Pages` workflow (`.github/workflows/pages.yml`) runs on every push to `main`, and you can also run it by hand from the Actions tab. It runs the app tests and then deploys.
4. The site goes up at `https://<you>.github.io/<repo>/`. Pages serves over HTTPS, so the mic works on your phone.

Pages on a **private** repo needs a paid GitHub plan (Pro or above). Free accounts need a public repo.

## Local development

```sh
cd app
npx serve      # then open http://localhost:3000 (the mic is allowed on localhost)
npm test       # synthetic-vowel analysis tests
```

To test on Android against a local server, use Chrome's USB port forwarding (`chrome://inspect` → Port forwarding → 3000). Mic access needs `localhost` or HTTPS.

## Re-running the analysis

```sh
analysis/.venv/Scripts/python.exe analysis/run.py recordings/week4
analysis/.venv/Scripts/python.exe analysis/compare.py analysis/results/baseline.json analysis/results/week4.json
```

To recreate the venv: install Python 3.14, run `python -m venv analysis/.venv`, then `analysis/.venv/Scripts/pip install -r analysis/requirements.txt`. The bench's synthetic vowels are regenerated by `bench/praat_truth.py`.
